# Clean Code 깊이 읽기

## 이 책이 다루는 문제

소프트웨어는 한 번 쓰고 버리는 글이 아닙니다. 같은 코드를 수십 명이, 수년에 걸쳐 읽습니다. 로버트 마틴은 이 단순한 사실에서 출발해 **"읽히는 코드"** 가 곧 좋은 코드라고 주장합니다.

## 핵심 개념 셋

- **의미 있는 이름**: 변수 이름 하나가 주석 열 줄을 대체합니다. `d` 대신 `elapsedDays`.
- **작은 함수**: 함수는 한 가지 일을 하고, 그 일을 잘하고, 그 일만 해야 합니다.
- **보이스카우트 규칙**: 처음 왔을 때보다 깨끗하게 떠나라. 거대한 리팩터링보다 작은 정리의 누적이 코드베이스를 살립니다.

> 코드는 작성되는 시간보다 읽히는 시간이 훨씬 길다.

## 비판적으로 읽기

모든 규칙을 교조적으로 따를 필요는 없습니다. "함수는 4줄 이내" 같은 극단적 주장은 현대 Swift/Kotlin 코드베이스에 그대로 적용하기 어렵습니다. 중요한 것은 규칙 자체가 아니라 **"이 코드를 처음 보는 동료가 이해할 수 있는가"** 라는 질문입니다.
